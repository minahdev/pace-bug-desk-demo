4단계에서 한 일

Haiku를 학생이라고 생각하면 쉬워요. 학생의 머리는 바꿀 수 없어요. 대신 학생에게 주는 프롬프트(지시문)를 바꿔 가며 모의고사 점수를 올렸어요.

회차는 "몇 번째로 바꿔 본 것"이라는 뜻이에요. 0회차가 출발점이고, 한 회차에서 두 가지로 나눠 해 보면 a, b를 붙였어요. 한 번에 한 가지만 바꿔야, 무엇 덕분에 점수가 바뀌었는지 알 수 있어요.

2회차 · 제목·목록으로 정리Markdown 템플릿92.9% → 92.1%

내용은 그대로 두고 모양만 정리했어요. 점수는 거의 그대로였어요. 모양만 바꿔서는 효과가 없다는 걸 확인했어요. 프롬프트가 길어질 걸 생각해서 정리는 남겼어요.

3회차 · 헷갈릴 때 규칙Rubric · 정보 부족 시 답변 불가92.1% → 96.2%

기준표의 "헷갈릴 때 고르는 순서" 5개 규칙을 넣었어요. 접수번호 2231번 건 어떻게 되고 있나요? 같은 지난 대화를 가리키는 글을 모두 판단 불가로 맞혔어요.

4회차 · 기능 목록Context 선별96.2% → 97.1%

PACE에 있는 기능과 없는 기능을 알려 줬어요. 신고 버튼도 없고 차단도 안 되네요를 고장이 아니라 개선 요청으로 맞혔어요. 개선 요청 정확도가 89.5%에서 97.4%로 올랐어요.

5회차 · 판단 불가 규칙 다듬기정보 부족 시 답변 불가97.1% → 99.2%

"이상해요", "뭔가 그래요" 같은 막연한 말은 증상이 아니라고 알려 줬어요. 폰으로 쓰다 보면 가끔 이상하게 될 때가 있어요 같은 글을 판단 불가로 맞혔어요. 240문제 중 2개만 틀렸어요.

① 정답을 붙인 기준이 달라요 (가장 큰 이유)

"픽셀 4a 폰에서 작동을 안 해요", "실내 러닝 페이스가 정확하지 않아요"를 우리는 버그로 봤어요. 리뷰에 정답을 붙인 연구자들은 "지원해 달라", "정확하게 해 달라"는 기능 요청으로 봤어요. Haiku가 틀렸다기보다 채점 기준이 달라요. 우리 기준표를 지키려고 일부러 맞추지 않았어요.

② 이미 해결된 문제를 버그라고 함

"고객센터에 메일 보낸 뒤 연결 문제가 해결됐고 지금은 만족해요"처럼 지금은 고장이 없는 글을 버그로 봤어요.

끝까지 못 맞힌 문제

러닝 후기 길게 쓰다가 실수로 뒤로가기 눌러서 30분 동안 쓴 게 다 날아갔어요. … 제가 잘못 누른 거긴 한데 … 임시저장 기능 꼭 만들어주세요

정답은 개선 요청이에요. 사용자가 직접 뒤로가기를 눌렀으니 앱은 정상대로 움직였어요. 바라는 건 임시저장 기능이에요.

Haiku는 어떤 프롬프트로도 "글이 날아간 걸 겪었으니 버그"라고 답했어요. 결과만 보고, 그게 고장인지 정상 동작인지는 따지지 않은 거예요. 시험지에서 가장 어려운 문제예요.

과제 필수 조건, 4단계에서 채운 것

16개 중 13개를 채웠고, 1개는 일부, 2개는 뒤 단계에서 해요.

  • 완료System·User 프롬프트 분리 (0·10회차)
  • 완료주요 파라미터 설정 (8회차 effort)
  • 완료Markdown 템플릿 (2회차)
  • 완료Few-shot (6회차)
  • 완료Decomposition·Prompt Chaining (9회차)
  • 완료CoT·Rubric (7회차·3회차)
  • 완료정보 부족 시 답변 불가 (3·5회차)
  • 완료Structured Outputs, JSON Schema (1회차)
  • 완료Prefix cache 고려 배치 (10회차)
  • 완료평가셋과 지표 (2단계 시험지, 목표 점수)
  • 완료Python 자동 채점 + CSV (채점 코드, 결과표)
  • 완료품질·응답시간·비용 비교 (모든 회차)
  • 완료Baseline 후 한 변수씩 개선 (0회차부터)
  • 일부Context 선별·위치 배치는 완료, 상태 관리는 8단계
  • 뒤에서Function calling (6단계, 기록부 찾기 도구)
  • 뒤에서여러 LLM 태스크 조합 (7·8단계)
