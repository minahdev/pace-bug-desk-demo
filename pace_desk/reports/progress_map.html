완료

한 줄 설명: 프롬프트를 Haiku에게 보내고 답을 받아 오는 코드예요. 받은 답은 저장해 두고 다시 써요. 모든 실험과 서비스가 이 코드 하나로 Haiku를 불러요.

부르는 방식을 바꿨어요

API 크레딧이 얼마 남지 않아서, API 키 대신 Claude Code 헤드리스 모드로 부르기로 했어요.

속도1번에 약 1초1번에 2~5초 (Claude Code를 켜고 끄는 시간), 여러 개를 동시에 불러서 줄여요
덧붙는 글없음약 650토큰 (환경·계정 안내). 모든 호출에 똑같이 붙어서 실험끼리 비교하는 데는 문제없어요
지금 쓰는 것이쪽을 써요

llm.py가 하는 일

  • 시스템 프롬프트(매번 같은 규칙)와 사용자 글(이번에 처리할 글)을 나눠서 보내요.
  • JSON 모양을 정해 주면 정확히 그 모양으로 답을 받아요.
  • 얼마나 깊이 생각할지(effort)를 정할 수 있어요.
  • 걸린 시간, 토큰, 비용을 매번 적어요.
  • 받은 답은 공책에 적어 두고 다시 써요. 같은 질문은 다시 전화하지 않아요. 사용 한도에 걸려 멈춰도 이어서 할 수 있어요.
  • 여러 개를 동시에 부르고, 사용 한도에 걸리면 바로 멈춰요.

구간 4~9 결과

  1. 4

    분류 실험 완료

    0~12회차를 시험해 7회차(규칙 + 기능 목록 + 이유 먼저 쓰기)를 골랐어요. 연습 문제 99.2%, 시험용 98.1%예요. 자세한 기록: 4단계 분류 실험 기록

  2. 5

    추출 실험 완료

    규칙과 예시 3개를 넣은 2회차를 골랐어요. 시험용에서 플랫폼·앱 버전 100%, 글에 없는 값 지어내기 0%예요.

  3. 6

    도구 완료

    기록부 검색 도구 세 개를 만들고, Haiku가 직접 부를 수 있게 도구 서버(MCP)로 연결했어요.

  4. 7

    연결·점수 완료

    Haiku가 도구로 직접 찾는 3회차를 골랐어요. 시험용에서 이슈 연결 96.3%, 우선순위 98.5%예요.

  5. 8

    웹 서비스 완료

    제보를 넣으면 분류, 연결된 이슈, 우선순위, 더 물어볼 것이 화면에 나와요. 부족한 정보를 덧붙이면 합쳐서 다시 분석해요. 제보 1건에 약 8초예요.

  6. 9

    최종 평가 완료

    시험용 문제를 한 번만 풀어 목표 지표를 모두 통과했어요. 결과: PACE 최종 평가 보고서

용어 사전

평가셋 (시험지)
정답이 붙은 문제 모음이에요. AI가 잘하는지 채점할 때 써요.
정답 (골드)
기준표대로 붙인 정답이에요.
연습용·시험용 (dev·test)
연습용으로 설명서를 다듬고, 시험용은 마지막에 한 번만 풀어요.
프롬프트 (설명서)
AI에게 주는 지시문이에요.
시스템 프롬프트
매번 같은 역할과 규칙이에요. 이번에 처리할 글은 사용자 프롬프트로 따로 줘요.
Few-shot
설명서에 예시 문제와 정답을 몇 개 같이 넣는 방법이에요.
CoT
답하기 전에 생각하는 단계를 적게 하는 방법이에요.
Rubric (기준표)
점수를 매기는 규칙표예요.
JSON Schema
답의 모양을 정한 틀이에요. 어떤 칸에 어떤 값만 넣을 수 있는지 정해요.
토큰
AI가 글을 세는 단위예요. 토큰이 많을수록 느리고 비싸져요.
effort
AI가 얼마나 깊이 생각할지 정하는 값이에요. 깊을수록 느리고 비싸요.
헤드리스 모드
Claude Code를 화면 없이 명령 한 줄로 부르는 방법이에요.
캐시 (공책)
한 번 받은 답을 저장해 두고 다시 쓰는 것이에요.
이중 채점
두 사람이 따로 풀어서 답이 다른 곳만 다시 보는 정답 확인 방법이에요.
제한 사항
고장이 아니라 원래 그렇게 만든 것이에요. 예: 사진은 10MB까지.
재발
고쳤던 문제가 다시 생긴 것이에요. 우선순위를 크게 올려요.
